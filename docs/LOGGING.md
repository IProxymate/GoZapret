# Документация по логированию GoZapret

## Обзор

GoZapret использует структурированное логирование на базе стандартной библиотеки `log/slog` из Go 1.21+. Логгер конфигурируется отдельным файлом, инициализируется в main и передается как зависимость.

## Архитектура

### Принципы
- **Dependency Injection**: логгер создается в main и передается всем компонентам
- **Отдельная конфигурация**: настройки логирования в отдельном файле `logger.json`
- **Простота**: минимум глобального состояния, явная передача зависимостей

### Компоненты
1. **logger.json** - файл конфигурации логирования
2. **internal/logger** - пакет для создания логгера
3. **main.go** - инициализация логгера
4. **App и сервисы** - получают логгер через конструктор

## Конфигурация

### Файл logger.json

Создайте файл `logger.json` в корне проекта:

```json
{
  "level": "info",
  "format": "text",
  "output": "both",
  "file_path": "",
  "max_size": 10,
  "max_backups": 5,
  "max_age": 30,
  "compress": true,
  "add_source": false
}
```

### Параметры

#### level (string)
Минимальный уровень логирования:
- `debug` - все сообщения, включая отладочные
- `info` - информационные сообщения и выше (по умолчанию)
- `warn` - предупреждения и ошибки
- `error` - только ошибки

#### format (string)
Формат вывода логов:
- `text` - текстовый формат, удобный для чтения (по умолчанию)
- `json` - JSON формат, удобный для парсинга

#### output (string)
Куда выводить логи:
- `stdout` - только в консоль
- `file` - только в файл
- `both` - и в консоль, и в файл (по умолчанию)

#### file_path (string)
Путь к файлу логов. Если пустой, используется:
`%USERPROFILE%/AppData/Local/Zapret/logs/app.log`

#### max_size (int)
Максимальный размер файла лога в мегабайтах перед ротацией. По умолчанию: `10`

#### max_backups (int)
Максимальное количество старых файлов логов. По умолчанию: `5`

#### max_age (int)
Максимальный возраст файлов логов в днях. По умолчанию: `30`

#### compress (bool)
Сжимать ли старые файлы логов. По умолчанию: `true`

#### add_source (bool)
Добавлять ли информацию об источнике (файл и строка). По умолчанию: `false`

## Использование

### Инициализация в main.go

```go
package main

import (
    "github.com/IProxymate/GoZapret/internal/logger"
    "github.com/IProxymate/GoZapret/internal/ui"
    "log/slog"
)

func main() {
    // Загружаем конфигурацию логирования
    logConfig, err := logger.LoadConfig("logger.json")
    if err != nil {
        slog.Warn("Ошибка загрузки конфигурации, используются настройки по умолчанию", "error", err)
        logConfig = logger.DefaultConfig()
    }

    // Создаем логгер
    log, err := logger.New(logConfig)
    if err != nil {
        slog.Error("Ошибка создания логгера", "error", err)
        return
    }

    // Устанавливаем как глобальный (опционально)
    slog.SetDefault(log)

    // Передаем логгер в приложение
    app := ui.NewApp(assets, log)
    app.Run()
}
```

### Передача логгера в компоненты

```go
// App принимает логгер через конструктор
type App struct {
    logger *slog.Logger
    // другие поля...
}

func NewApp(assets embed.FS, logger *slog.Logger) *App {
    return &App{
        logger: logger,
        // инициализация других полей...
    }
}

// Использование логгера в методах
func (a *App) someMethod() {
    a.logger.Info("Сообщение", "key", "value")
    a.logger.Error("Ошибка", "error", err)
}
```

### Создание дочерних логгеров

```go
// Логгер с постоянными атрибутами
serviceLogger := logger.With("service", "process_manager", "version", "1.0")
serviceLogger.Info("Сервис инициализирован")

// Логгер с группой
dbLogger := logger.WithGroup("database")
dbLogger.Info("Подключение установлено", "host", "localhost")
```

### Примеры логирования

```go
// Информационное сообщение
logger.Info("Приложение запущено")

// С атрибутами
logger.Info("Стратегия запущена", "strategy", "general", "pid", 1234)

// Предупреждение
logger.Warn("Нет прав администратора", "user", "current_user")

// Ошибка
logger.Error("Не удалось запустить процесс", "error", err)

// Отладка (только при level=debug)
logger.Debug("Проверка процесса", "pid", 1234, "status", "running")
```

## Ротация логов

Ротация происходит автоматически при достижении `max_size` МБ.

Старые файлы именуются:
- `app-2025-01-17T20-00-00.log` - несжатый
- `app-2025-01-17T20-00-00.log.gz` - сжатый (если `compress: true`)

Автоматически удаляются файлы:
- Старше `max_age` дней
- Превышающие `max_backups`

## Примеры логов

### Текстовый формат

```
2025-01-17 20:00:00 level=INFO msg="Запуск приложения GoZapret"
2025-01-17 20:00:01 level=INFO msg="Конфигурация загружена"
2025-01-17 20:00:02 level=INFO msg="Стратегия запущена" strategy=general pid=1234
```

### JSON формат

```json
{"time":"2025-01-17 20:00:00","level":"INFO","msg":"Запуск приложения GoZapret"}
{"time":"2025-01-17 20:00:01","level":"INFO","msg":"Конфигурация загружена"}
{"time":"2025-01-17 20:00:02","level":"INFO","msg":"Стратегия запущена","strategy":"general","pid":1234}
```

## Рекомендации

### Уровни логирования
- **Продакшен**: `info` или `warn`
- **Разработка**: `debug`
- **Отладка проблем**: `debug` с `add_source: true`

### Форматы
- **Продакшен**: `json` (легко парсить)
- **Разработка**: `text` (легко читать)

### Размеры и ротация
- `max_size`: 10-50 МБ
- `max_backups`: 5-10 файлов
- `compress`: всегда `true`

### Структура логов
```go
// Хорошо: структурированные атрибуты
logger.Info("Процесс запущен", "pid", 1234, "strategy", "general")

// Плохо: всё в сообщении
logger.Info("Процесс 1234 запущен со стратегией general")
```

## Устранение проблем

### Логи не записываются
1. Проверьте права доступа к директории
2. Убедитесь, что `output` = `file` или `both`
3. Проверьте путь в `file_path`

### Слишком много файлов
1. Уменьшите `max_backups`
2. Уменьшите `max_age`
3. Увеличьте `max_size`

### Логи занимают много места
1. Включите `compress: true`
2. Уменьшите `max_backups` и `max_age`
3. Повысьте уровень до `warn` или `error`

### Не видно debug сообщений
1. Установите `level: "debug"` в `logger.json`
2. Перезапустите приложение

## Преимущества подхода

✅ **Простота** - логгер создается в одном месте  
✅ **Явность** - зависимости передаются явно  
✅ **Тестируемость** - легко подменить логгер в тестах  
✅ **Гибкость** - легко изменить конфигурацию  
✅ **Независимость** - конфигурация отдельно от кода
